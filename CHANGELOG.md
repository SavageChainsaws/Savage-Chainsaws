# Changelog

Owned by Stem. One line per change: date, who, what, and why if it's not obvious. Everyone on the team — Claude, Stem, App Bot, New Bot, Financial Bot — checks this file and `docs/HANDOFF.md` before building anything new, and adds a line here for every change they make. Newest entries on top.

Only Claude writes code or runs migrations (see `docs/HANDOFF.md` §7) — an entry here from a bot describes data it entered or an action it took through an existing API route, never a code or schema change.

## 2026-11-09

- **[Claude]** Fixed real correctness/safety bugs Stem caught in its read-only review of the bot-access PR before any merge: reminders now gate on `sent_at` (not `status`, which is set at PDF-creation time before any email ever goes out); `forbiddenInvoicePatchReason` now actually checks the route's real `parts_line_items`/`labor_line_items` payload keys (it previously checked keys the route never sends, so the amount-change guard never fired) and now also blocks `due_date` (admin-only - App Bot can no longer write it at all); idempotency now claims the key *before* running the side effect instead of after (closing a race where two concurrent retries could both run), and no longer caches a 5xx as a permanent "replay"; the reminder throttle itself moved to an atomic Postgres function (`claim_invoice_reminder`, advisory-locked per invoice) instead of a check-then-insert race in app code; customer/unit matching no longer uses raw `ilike` (escapes `%`/`_`, checks `secondary_email`, handles a concurrent unique-violation as a found match instead of an error); the reminder path now fails closed on any payment-check error, verifies the provider's paid amount against the invoice's own amount (Square tenders included) before trusting "paid", refreshes-or-refuses an expired Stripe Checkout link instead of emailing a dead one, and skips archived invoices, invoices with an unresolved Zelle claim, and invoices on an active payment plan; `/api/bot/financial/installments` now reads real `invoice_installments`/`invoice_payment_plans` rows instead of just the `payment_plan_offered` flag; the financial summary excludes archived write-offs from outstanding and flags a `truncated` result if it hits the row cap; bot-created invoice drafts now apply the same first-service referral discount the admin flows do and reject a negative total; `units.serial_number` (NOT NULL) is never sent `null` from the bot route; the duplicate-unit index now trims before lowercasing, consistent with its own `WHERE` clause; every bot read (not just writes) is now audited; `GET /api/bot/app/customers?id=` no longer `select('*')`s; added a test for a revoked token. Re-verified the live-data duplicate check against the corrected index expression - still clean. **Still not applied/deployed - same approval gate as below.**
- **[Claude]** Built App Bot and Financial Bot access: individually-revocable bearer tokens (never stored/logged/committed as plaintext — see `/bot-tokens`), scoped `/api/bot/app/*` and `/api/bot/financial/*` routes, server-side permission enforcement (RLS can't gate a tokenless bot), full audit log (`bot_audit_log`), idempotency-key protection on every mutating endpoint, and duplicate-match safeguards for bot-created customers/units (`lib/bot/rules.ts`'s `resolveMatch()` — ambiguous matches need Jesse's review, never auto-created). Added `invoices.due_date` (no backfill, no assumed NET 30 — Jesse confirms per-invoice at `/invoices`), `service_history.hour_meter`/`.parts_used` (kept separate from labor hours), and a partial unique index on `units(customer_id, serial_number)` excluding placeholder values. Added Vitest and unit tests for the new `lib/bot/*` rules (forbidden actions, duplicate-reminder throttling, idempotent retries, dedup matching). **Migration not yet applied to the live database; routes not yet deployed — pending Jesse's go-ahead (see the PR).**
- **[Claude]** Updated `docs/HANDOFF.md` (§2, §3, §4, §5, §6, §7, §8, quick-start) to describe the above.
